# Seed 知识库维护机制

> 本文件是 seed-kb 的运行规程：任何新材料进入知识库，都按本机制执行。设计原则：**宁慢勿漏**——阅读完整性优先于产出速度；**冲突不静默**——凡与存量知识矛盾的必须显式裁决；**03 是唯一知识源**——HTML 只是渲染产物。

## 1. 资产地图（谁是谁）

| 资产 | 角色 | 更新规则 |
|---|---|---|
| `tools/intake/` | 进料区：每份新材料一个子目录（原始件、阅读笔记、知识点清单） | 只增不改 |
| `02/03/05/04` | 02 题库、**03 知识手册（唯一知识源）**、05 桌面版、04 便携版 | 只能由阶段五流程修改 |
| `06` | 滚动台账：材料登记、裁决记录、变更日志 | 每次进料追加 |
| `tools/` | 抓取/构建脚本、全文缓存、图片库 | 可复用，随用随扩 |

## 2. 流水线总览

```
新材料 → ①登记 → ②完整阅读 → ③知识点抽取 → ④对照裁决 → ⑤写入门禁 → 交付物更新 + 台账追加
              ↑______________________________________________|
              （②未达完成判据，禁止进入④；这是硬闸门）
```

## 3. 阶段一：接收与登记

1. 在 `tools/intake/` 建目录：`NNN-材料短名/`（NNN 三位递增）。
2. 登记：来源与链接、接收日期、格式（文档/网页/图片/口述/代码库）、体量初测（章节数、估算字符量、图片数）。
3. 在 06 台账"材料登记表"追加一行，状态置为 `阅读中`。

## 4. 阶段二：完整阅读协议（硬闸门）

教训背景：首次处理 73 万字符文档时只读了前 1/7 就开始产出，导致返工。本协议即为杜绝此类问题。

1. **先测体量，后动内容**：探测总高度/总字符/图片总数/章节骨架（注意虚拟渲染：目录取"滚动后的全量"，正文章节标题取"最后一次出现"而非第一次）。
2. **分片全文遍历**：按固定步长滚动抓全文，进度落盘可续传；大体量材料分多次会话读完，`intake/` 里留阅读进度标记。
3. **完整性自检（完成判据）**：材料地图上的章节清单逐节打勾，章节覆盖率 = 100% 才算读完；图片清单同样处理。自检结果写入 `intake/NNN/阅读笔记.md` 头部。
4. 明确不读的部分（目录、广告、无关附录）也要在笔记里**显式列出并说明不读理由**——"没读"和"判定不必读"是两回事。

## 5. 阶段三：知识点抽取

读完后产出 `intake/NNN/知识点清单.md`，每条一张卡片：

```
KP-NNN-序号 | 主题：所属知识域（对应手册章节）
内容：一句话结论 + 必要细节
证据强度：A 实测数据/官方文档 > B 多方一致的实践 > C 单一实践案例 > D 个人观点/转述
（若为转述数据：标注"待自证"，不得直接写死进正文）
```

## 6. 阶段四：对照裁决（核心判定表）

每张知识卡片与 03 存量逐一对照，判定为五类之一：

| 判定 | 定义 | 动作 | 落点 |
|---|---|---|---|
| **一致** | 已有且无增量 | 不改正文；可在台账记"旁证+1"提升该知识点置信度 | 仅台账 |
| **进化** | 已有，但新材料更深/更新/带数据 | **补充**进现有小节：改写表述、并入新数据，旧表述不留双版本 | 03 对应章节 |
| **冲突** | 与存量结论矛盾 | 走裁决流程（见下），禁止静默二选一 | 03 + 台账裁决记录 |
| **新增** | 全新主题/知识点 | **新增**小节，挂在最近的父主题下；够不成体系则攒到同域 ≥3 条再立新章 | 03 新小节 |
| **失效** | 存量被证明过时/错误 | **剔除**：正文删除；有历史价值的移入附录"历史口径"并注明原因 | 03 + 台账 |

**冲突裁决规则**：①比证据强度（A>B>C>D，实测数据压经验）；②比时效（新口径取代旧口径，但注明适用条件是否改变）；③两者并存且各有适用场景时，改写为"按条件分支"表述；④证据同级且无法判定 → 挂起（记入台账"待证区"，不入正文，下次材料优先核查）。

## 7. 阶段五：写入与门禁

顺序固定：**先改 03 → 再同步 04/05 模板 → 重建 HTML → 过校验清单**。

校验清单（全部通过才算完成）：
- [ ] 03 章节与知识点清单对账一致（可用 06 的对照表格式复查）
- [ ] 04/05 与 03 内容同步（逐处变更核对，两份不许漂移）
- [ ] HTML 零出处字样（自动查"原文/原素材/原始素材/快照"= 0）
- [ ] 深色主题（05）/便携规范（04）未被破坏；徽标日期与图片计数已更新
- [ ] 配图规则：无明确用途标注的图不进正文；新图先辨认后嵌入
- [ ] HTML 重建后浏览器实际打开抽查 ≥2 处变更点

完成后：04/05 徽标日期改为本次更新日；06 台账该材料状态置 `已消化`，追加变更日志（哪些章节、哪类判定、各几条）。

## 8. 特殊情况

- **材料本身是 HTML/网页**：优先抓全文落盘再解析，不在浏览器里即读即判。
- **材料之间互斥**（两份新材料互相矛盾）：各自先与 03 对照，再按冲突裁决规则处理，台账记录三方关系。
- **大体量材料（>20 万字符）**：允许跨会话，但必须在 intake 目录留"读到哪里"的断点，重开会话先续读后动作。
- **只想要速览**：用户明确说"不用入库"时，只出摘要不动知识库，但仍执行阶段二的完整阅读。

## 9. 机制的边界

本机制管"知识入库"，不管：一次性问答（不落盘）、题库增补（走 02 的追加格式，判定表同样适用）、图片库维护（随材料进 intake，精选后入 tools/imgs）。
